# Testing and evidence

All application compilation and execution checks run in GitHub Actions on the exact commit. The six native target rows are required, with maximum three concurrently hosted jobs, two build/test/native threads per runner, command/HTTP/job bounds and owned process cleanup. Missing jobs, wrong source SHA and missing reports fail the aggregate; no broad continue-on-error or fake passing badges.

## Tiers

1. Portable core contracts: rational source PTS, overflow, Unicode/long-hour export, strict parser, geometry, repeated appearances, checkpoint restoration and edit rollback. Tiny literal fixtures and bounded property cases avoid network/native startup. Public boundary fixtures cover exact source-time arithmetic, strict timecode components, cue identities, confidence-selected evidence, direct invalid split preservation and undo/redo availability. Separate native-speed stress cases exercise the exact 50-edit/32-MiB retention boundaries, one oversized recoverable snapshot and the exact 64-MiB subtitle input limit; those necessary large allocations are excluded from Miri, not from native tests or the critical mutation campaign.
2. Native contracts: real atomic files/locks, verified model/runtime metadata and native media/decode paths. Synthetic extraction uses actual FFmpeg and ONNX, not a mocked recognizer. The selected FFmpeg build includes `avdevice` for the existing `lavfi` color source; fixture generation must succeed with the declared timing/text recipe before OCR is exercised. The English fixture reuses immutable Noto Sans bytes and its OFL notice instead of choosing different OS fonts. Two bounded 30-second resource requests plus the existing 30-second renderer fit a 120-second outer/60-second idle guard. The literal Hello, repeated-appearance and valid-timing assertions remain unchanged; this input normalization does not prove the Apple Silicon recognition failure resolved.
   A separate hosted `xtask ocr-evidence` pass records only the first frame of that generated English fixture before the unchanged CLI smoke. It compares native RGB with the admitted FFmpeg CLI's bilinear RGB reference, retains frame/ROI/DB crops, and observes the actual shared detector/recognizer input/output tensors synchronously. Tensor files use explicit little-endian f32 bits, checked shapes, finite counts, SHA256 and bounded top-1 data; total tensor output is capped at64MiB, eight crops per image,90 seconds cooperative/120 seconds outer and60 seconds idle. Ordinary extraction uses no observer and writes no additional image/tensor diagnostics. These artifacts localize divergence; they neither change the selected model/provider/fallback/confidence policy nor assert that cross-platform floating-point output must be bit-identical. Two tiny literal summary/comparison contracts run in the existing xtask suite. Windows additionally initializes the verifier from a copied, hash-verified model in a canonical Unicode/spaced directory, rejects and preserves a corrupted copy, removes the temporary model directory, and then recognizes using the initialized engine. The ordinary smoke and relocated package extraction remain required. This regression's execution is pending.
3. Actual instrumented GUI: native startup/source admission/preview, themes, model-catalog verification, full language selection, persisted automatic-update disable, native diagnostics without repair approval, Start job, review edits and exported Unicode bytes. The catalog check requires all four admitted IDs to match their displayed headings and actual install/import/export controls. The same session verifies123 language options, Russian Tesseract routing and representative nonpriority extraction choices; it does not download packs or certify their OCR. Settings checks wait for the actual enabled preference and completed save before inspecting persisted bytes; diagnostics require native FFmpeg verification and an unapproved disabled repair control. W3C WebDriver acts through ordinary controls; only fixed test grants bypass OS picker interaction. It never patches application state. DOM/styles/screenshots are actual artifacts when the hosted scenario passes. Desktop state is retrieved only after Tauri Ready/setup has registered it. The optional driver is pinned to upstream commit `50e7509073ca47dbf2f42a965d8161c198b96ac3`, which aligns its Windows COM types with Tauri 2.12; released driver 0.2.3 has incompatible older Windows crate identities. Production still excludes the driver. Failed GUI captures and explicitly synthetic fixture/SRT/checkpoint artifacts are retained for diagnosis; successful-looking server readiness alone is not frontend readiness.
4. Standalone package: matching native executables/resources and hashes, launch from a relocated directory with spaces, no checkout library path dependency, offline model load and actual extraction. Both CLI and production GUI child commands remove inherited loader overrides and checkout runtime PATH entries; a pure command-environment contract also checks that unrelated data-root settings survive. Installer/ABI checks have separate evidence.
5. Qualification: independently annotated real en/fa/ja hardsub data, CER/WER/event recall/source-frame boundaries, coverage/mutation/fuzz/Miri/sanitizers and physical GPU placement/performance. Missing qualification does not become PASS because CPU smoke succeeds.

## Planned thresholds

English CER ≤2%; Persian/Japanese CER ≤5%; accurate-mode event recall ≥98%; p95 boundary error ≤max(100ms, two displayed-frame intervals). Allowed precision-related CER regression ≤0.5 percentage points. Instrumentable owned Rust coverage ≥80%; timing/tracking/export/persistence and changed lines ≥90%; reviewed critical mutations ≥80%. These are acceptance targets, not measured results.

Before native provisioning, `scripts/ci/guard-tests.ps1` exercises the real guard with captured Unicode output, nonzero exit propagation, a deliberately surviving child that must be rejected and reaped, a quiet build with actual log writes and a frozen-log idle failure. Each command has a 15-second wall/5-second idle ceiling; the regression step has a two-minute ceiling. Interpreter lookup selects one executable; exited root handles are released before owned-tree accounting, with a two-second bounded stream/teardown grace. Windows job checks enumerate actual associated process IDs and probe signaled process handles rather than counting retained terminated process objects as live descendants; PID reuse outside the owned job is excluded. A Windows-only regression holds a real exited child's process handle outside the job until the guard has returned, using an explicit PID/start-time signal rather than a startup sleep. Live descendants still fail the guard. Native vcpkg builds write stage logs directly in their port directories. The guard advances shallow root/immediate-port `*.log` metadata pages every 250ms, never recursively traversing extracted source. Each tick processes at most 128 entries or 100ms of work; the complete cycle still admits at most 512 port directories and 8192 logs. A checked one-second ceiling detects a slow individual metadata operation. Enumeration already supplies fresh size/write/attribute data, avoiding duplicate refresh calls. The first cycle establishes a baseline without counting existing log files as progress; directory/file enumerators are closed on completed cycles and every cleanup path. Missing/linked/failed metadata rejects the command. The synchronous ceiling is checked between I/O operations, not a claim of preemptive filesystem cancellation. Only real changed/new nonempty build logs count as progress; existing logs, deletion, nested source-log churn and process liveness do not. The quiet/frozen contracts include 43 port directories with 172 unchanged baseline logs (more than one sampler page), bulk extracted-source noise and a continuously changing nested `noise.log` that must not prevent idle failure. Frozen output/logs still trigger the unchanged idle ceiling. Post-exit errors record the root exit code, live-tree count, bounded owned PID/process names and pending stream states without relaxing the two-second teardown bound; names are diagnostic only, never permission to ignore or terminate unrelated processes.

The same pre-provisioning step runs `scripts/ci/frontend-tests.ps1` under a20-second wall/10-second idle guard. Four cases execute the unchanged frontend script from an isolated layout, replacing only the expensive Trunk process boundary: production/E2E × success/controlled failure. They require instrumentation keys to be absent during the build, preserve exact native ARM helper pins, and verify absent, present-empty and populated Unicode values are restored even after failure. Actual Trunk builds remain the integration check; this contract neither compiles WASM nor proves bundler success. Process snapshots and environment-provider removal avoid PowerShell7.5+'s .NET null-to-empty conversion. The bundler uses the same removal/restoration semantics for its scoped variables without logging signing values. New regression execution is pending hosted verification.

Every created test is audited before its run: load-bearing assertions, cheapest evidence tier, shared immutable setup, isolated mutable state, bounded waits, two-worker ceiling and full owned-tree cleanup. Initial measured wall times are unknown until the first hosted run. No test is run locally and again in CI.

## Maintenance and language checks

Portable tests cover daily cadence/disable/manual policy, stable SemVer precedence (a build-metadata-only difference is not a newer release), consent, official catalog identities and explicit recognizer routing. App tests cover signed-metadata rejection, bounded preferences, native-pack inventory and actual ELF/PE/Mach-O archive admission using tiny generated headers; those fixtures are parser checks, never functioning application packages or signature qualification. Native media has its own once-per-target ABI/health/callback suite. Header-major constants are converted explicitly to the portable unsigned health fields; actual loaded versions must still match the separately compiled majors. Compiler success alone is not native loader admission. Actual six-target extraction/preview witnesses also cover packet draining with the platform EAGAIN constant rather than a Linux numeric errno; other decoder errors must still fail. Desktop contracts check disabled automatic checks and shared operation ownership without contacting a release feed.

`xtask maintenance` executes five actual CLI subprocesses serially (10-second wall/5-second idle each, 55-second inner total, outer guard90/30). It copies the CLI with only imported release CRT on Windows into a fresh Unicode/spaced path and uses empty native/data directories. A child-only loopback proxy tripwire rejects proxy-observable HTTP attempts; it is not OS network isolation. The hosted maintenance CLI witness is distinct from positive signed-repair/update lifecycle tests. It must launch the real CLI without media dependencies, assert precise missing-resource/denied-repair/invalid-language errors and discover the actual catalog. Missing positive signed download/install/restart and representative nonpriority-script OCR proof remain open; pure metadata or catalog tests do not replace them.

`xtask multilingual` installs only five selected official packs in isolated test data and renders five two-second/four-frame hardsub clips using pinned Noto fonts and their original OFL1.1 notices. It executes the actual CLI for French, Russian, Arabic, Hindi and Korean, requires known literal words in parsed SRT, valid source times/completed checkpoint identities and the expected recognizer diagnostic, then re-recognizes a Russian cue through the app service. Font downloads are byte/hash bounded; existing native models are reused without changing baseline package data. The single serial hosted command has480 seconds inner/510 seconds outer and90 seconds idle; each install/render/extract is bounded. Unix additionally starts the real isolated worker paused at a durable checkpoint, closes only its parent-lifetime pipe, and requires SIGKILL/reap within three seconds with no exported output. The supervisor retains the pipe separately from `Child::wait`; its worker-side EOF guardian preserves process-group isolation when the parent is forcibly killed. The direct EOF witness verifies that lease boundary, not every possible kernel/native stall or descendant scenario. Readiness is condition-based and bounded to15 seconds; exact owned-group cleanup runs on failure. Windows retains its existing Job Object boundary. This is synthetic integration/lifecycle coverage only, not real-subtitle quality or all123-language qualification. At exact `cb8db1b` these synthetic witnesses passed on Linux x64/ARM64 and Intel macOS; other targets did not reach them. They do not qualify all languages or real subtitle accuracy.

`xtask runtime-pack` produces target-prefixed candidate dependency assets only in hosted Actions. It reuses finalized same-source/target/lock native inventory, archives bounded regular notice files, signs the manifest with the approved updater key, re-authenticates it, requires modified signed metadata to fail, runs the real CLI native API diagnostics against staged resources, and rechecks final emitted payload hashes/metadata before reporting. Signing inputs are scoped to this step and removed from the diagnostic child. These checks do not prove the public download/repair/restart path or supply platform-native signing. Unix repair restores owner execution only for the signed visual helper; its permission regression is separate from OCR inference.

`xtask update-assets` consumes verified same-source native bundles without rebuilding. It copies explicit format assets, signs and verifies streamed payload bytes plus authenticated version, refuses a different announced version for the same signature, runs structural target admission, and signs an internal candidate manifest. The candidate is never named `latest.json` or published by this step. Windows/Apple platform-signing and actual install/update/uninstall tests remain independent blockers; an updater signature cannot promote an unsigned native intermediate to a final distributable.

The existing offline partial-download regression additionally requires pre-cancelled complete bytes to remain unactivated and preserved. Shared model/language transfer source now checks a total deadline and cancellation through final hash/copy and before atomic persistence; late-read cancellation and slow-transfer fault execution are not established by that offline case and remain required hosted evidence.

All CI lanes are children of the manual Final verification root. No local application test or compilation fallback is authorized. Native final signing/publication remains blocked when approved platform credentials are unavailable.

## Evidence integrity

Synthetic media cannot certify real OCR quality. Automatic OCR/VLM labels cannot certify themselves as ground truth. A real screenshot is not proof of exact colors or IME composition; computed styles and dedicated composition/keyboard scenarios are required. Provider availability cannot prove GPU operator execution. `docs/validation.md` separates authored, not-run, failed and verified states.
