# CI matrix and evidence

Six hosted native targets are pinned in [targets.json](../ci/targets.json): Ubuntu 24.04 x64/ARM64, Windows 2025 x64/Windows 11 ARM64, macOS 15 Intel/ARM64. Three concurrent native jobs, two build/test/native threads per runner. All application compilation happens in Actions, never locally. Dependency maintenance uses one root Cargo workspace/lockfile entry; its seven explicit workspace members are discovered together rather than scheduled as overlapping independent updater jobs.

Desktop CI builds target-native FFmpeg/Tesseract/ORT and the Rust CLI, WASM frontend and Tauri GUI. It runs every owned package's contract suites, a relocated actual CLI witness with empty native resources/denied repair/invalid language/full catalog, actual native extraction, five isolated representative-script CLI extraction witnesses and Russian app-service reOCR, twelve instrumented GUI control/style/branding/edit/export behaviors, relocated portable CLI, production native-window lifecycle without WebDriver and installer content inventories. Libtest reports must contain nonzero tests with no failed/ignored/filtered cases. Command guard owns the process group/Job Object and enforces wall/idle ceilings; any leftover descendant rejects success. Only successful target-specific native dependency binary caches are retained for subsequent hosted runs, keyed by runner/native inputs; application builds, tests and exact-SHA reports never come from this cache. Pull requests do not promote caches to the default branch. The pinned Trunk CI tool is compiled natively with tool-only release LTO disabled and 16 codegen units to avoid unnecessary whole-program optimization during installation; two shared workers and the same wall/idle ceilings apply. Intel macOS provisions Tauri CLI 2.12.4 from its exact official native release ZIP instead of repeating the source installation that exceeded its 1,200-second wall ceiling. CI verifies the fixed archive byte count and SHA256, exact safe entry inventory, `lipo` native x86_64 architecture and installed CLI version before use. Other targets retain native source installation; no unverified archive or cross-architecture emulation is substituted. Application CLI/GUI/WASM release profiles and quality gates are unchanged. The frontend scope removes native instrumentation/helper overrides with the PowerShell environment provider and restores exact absence/empty/value states in `finally`; .NET null conversion must not create an empty helper version. A bounded four-case script-boundary regression runs before provisioning, while actual E2E/production Trunk builds remain mandatory. Windows ARM64 additionally provisions the exact matching native wasm-bindgen CLI0.2.129 and Binaryen133 optimizer before Trunk: archive/tool bytes, SHA256, safe member inventory, native ARM64 PE and actual versions must all match. This originally covered Trunk0.21.14's unsupported ARM helper-download route. The pending stable0.22.1 refresh retains those exact admitted native helper versions, without x64 emulation or disabling WASM optimization; its changed artifact hashing and dist locking still require all six actual frontend builds. Intel GUI compilation retains its release profile and1800-second wall/360-second idle limits; stable Cargo `--timings -vv` records real compiler-stage evidence, not a synthetic heartbeat. A previous silent interval is not proof of a deadlock or license to enlarge its timeout.

Native Linux x64 coverage collects the same contract/integration executions using LLVM instrumentation. Its ≥80% overall and ≥90% critical native-source floors are enforced. This is not a claim of full WASM UI/changed-line/platform-union coverage: those remain release-qualification requirements. Mutation and Miri are separate portable quality lanes, not duplicate native execution. A newly authored Linux x64 parser-fuzz lane uses the actual public SRT parser and six maintained seeds, pinned nightly/cargo-fuzz/libfuzzer-sys, explicit ASan and one30-second bounded campaign; source-bound nonzero execution/coverage, seed replay, zero failure artifacts and owned cleanup are required. It is not yet executed, and neither native FFI instrumentation nor complete fuzz qualification is inferred. Mutation copies respect the committed gitignore to avoid copying their own generated work trees; generated tool packages are excluded from the application Cargo workspace while remaining inside project-owned temporary directories. Miri keeps interpreter isolation and all UB/leak/race checks enabled; only property failure-file persistence is disabled within its interpreted environment, with explicit case/seed settings. Native property tests keep persistence. Mutation passes libtest options through both Cargo delimiters. CodeQL Rust/Actions and RustSec/license/source-policy checks are required.

Every report/artifact is bound to GITHUB_SHA. Missing, failed, skipped, wrong-source and zero-test evidence fail the relevant gate. Development CI is not release qualification: real independently annotated en/fa/ja quality, reviewed critical mutations, physical acceleration, signing and installer/update/uninstall evidence remain explicit gates. The separate manual release-qualification workflow cannot publish or manufacture missing evidence. **Final verification** (`verify.yml`) is the single manual CI root, calling the native, portable, supply-chain and CodeQL workflows as same-commit reusable children. No push/PR event initiates those lanes. Native media is explicitly built as a same-target release cdylib, relocated before hashing, and tested once per native row; package admission rejects missing/wrong-source/target/lock/closure inventory. Candidate runtime assets additionally require the explicit updater signing secret, authenticated exact metadata, actual staged native API health and final-output hash readback. Candidate updater artifacts reuse the verified native bundles and require streamed payload/signature/version verification plus actual format admission; candidate metadata never becomes a stable feed or a publication. Native bundle content checks require the real format marker, with exact expected GUI byte replacement for NSIS/deb/rpm; AppImage loader relocation has a distinct architecture/closure witness. None of these unsigned internal content witnesses constitutes a completed signed app build. Final signed publication is blocked when Windows/Apple signing inputs are unavailable; an updater key is not platform signing.
