## Findings and implemented corrections

### UI-01 — Queued source admission can display the previous video's image

**Impact: important.** A user can inspect a frame from video A while the loaded Review project and source metadata describe video B. The old `start_saved` completion assigned the new source directly. It did not invalidate the old preview generation, clear the old object URL or reset time. When the completed B project loaded, its fingerprint matched the newly assigned source, so the normal mismatch guard did not clear A's image.

**Reproduction:** admit B and add it to Queue; display a visually different A; start B through its ordinary Queue action; wait for B's completed Review without clicking a cue or seeking. The original state transition could retain A's pixels under B's metadata. A second race exists when an actual A decode completes after B is admitted.

**Correction:** `source_admission.rs` centralizes replacement, revokes the previous owned image URL, clears position, invalidates preview/source epochs and resets transport state. `accept_started_source` uses that path for queued/resumed jobs. Loading an unlinked project uses the same invalidation. Loading a matching project retains a valid frame, but requests a frame if none exists. An outstanding decode keeps ownership of `preview_busy` until its completion; source replacement does not start an overlapping native request. Stale completions are retired and the pending current source drains afterward.

**Regression obligations:** five host tests cover ordinary queued admission, regrant of the same fingerprint, matching and mismatching project loads, single URL retirement and retained request ownership. The hosted Queue witness uses two genuinely different native videos, then checks B's dimensions and sampled decoded pixels without a corrective seek. A separate held-response witness delays a successful native A decode, admits B, checks that A disappears immediately, releases A, and verifies B's pixels, one in-flight owner, one live URL and retirement of the stale URL. Its wrapper forwards real native calls and restores the original Tauri namespace; it does not substitute a fake decoded image.

### UI-02 — Frame controls use fixed 40 ms rather than adjacent source frames

**Impact: moderate.** Previous/Next frame and the corresponding unmodified arrow keys were implemented as fixed time offsets. At 24 fps they can redisplay the same frame; at 60 fps they can skip frames. Variable frame intervals cannot be represented correctly by a single constant or nominal average frame rate.

**Correction:** the supervised native request now supports a bounded `TransportFrame` operation. It returns actual frame PTS, estimated duration and binary PNG bytes through `preview_transport`. The decoder chooses the nearest preceding/following source timestamp and clamps at the clip edges. Backward stepping seeks just before the reference, retaining preroll across keyframe boundaries. The old ordinary PNG preview contract remains available to its other callers. Desktop ACL and command-manifest tests include the new command; native validation rejects invalid steps or inconsistent response metadata.

The UI uses the returned timestamp as displayed-frame authority. It coalesces repeated pending step actions and retains one native request. Shift-arrow time jumps remain separately defined. The binary envelope has a fixed 24-byte header, an 8 MiB PNG bound, explicit metadata limits and a PNG signature check; it does not serialize image bytes as JSON integers.

**Regression obligations:** literal 24/60 fps and irregular PTS selection, first/last boundaries, metadata rather than requested seek time, malformed packet/step rejection, actual native 24/60 fps lossless video pixels and unchanged input bytes. The hosted 10 fps fixture checks button and programmatic keyboard PTS, then `1000 → 900 → 1000` across an explicit 10-frame GOP. Programmatic keyboard events do not claim physical keyboard traversal.

### UI-03 — Playback falls behind elapsed time when decoding is slow

**Impact: moderate.** The old timer added 250 ms only when preview work was idle. A slower decode discarded elapsed ticks, so playback speed depended on decode latency.

**Correction:** the extracted `Transport` state machine anchors to a monotonic clock and queues the most recent requested position while the single current decode completes. Clock ticks do not invalidate every older successful image; otherwise slow continuous decoding would leave the viewer frozen. Explicit seeks, source changes and stepping invalidate superseded intent. Current native errors stop playback and remain visible. Pause, seek, stop and source replacement reanchor or stop the clock. A separate ended state ensures Play restarts after the last real frame PTS, which is usually earlier than the media duration. Play issued during active and queued frame steps waits for the final selected PTS before releasing the clock.

**Regression obligations:** repeated 400 ms decodes crossing 250 ms ticks still publish successive frames; latest seek coalescing; surfaced current failures; pause/resume without counting paused time; clock regression clamp; end/restart after final frame publication; explicit seek invalidation; playback-to-step interaction; active plus queued step followed by Play; pause cancellation; same/different source admission and duplicate completions. The hosted witness checks actual elapsed playback position, stable pause, manual seek interruption and end restart within existing timeout bounds. It does not certify a fixed rendering frame rate or audio synchronization.

**2026-11-25 review follow-up:** three additional playback edge cases share a distinction between the requested logical position and the decoded covering frame's PTS. Repeated +1 s requests on sparse source frames at 0/2000 ms could request 1000, publish PTS 0, and then request 1000 again. A manual endpoint seek 5999 could publish PTS 5900 while clearing the natural-end flag, so the first Play immediately ended instead of restarting. Finally, extraction Start is deliberately retained on source replacement; an out-of-range Start from a longer source bypassed the source-duration clamp during natural-end restart.

The correction preserves both authorities: time jumps accumulate from `Transport.position`, while adjacent-frame steps update that position from the actual returned PTS. Displayed frame values, range marks and the documented paused UI continue using source PTS. Play recognizes a logical endpoint even after the earlier covering frame is published, preserves pending or active backward frame actions, and validates restart against the current source endpoint. An in-range Start is retained; an out-of-range Start restarts playback at 0 without modifying extraction configuration. Four additional regression functions cover sparse positive/negative jumps and adjacent-step reanchoring, manual endpoint restart, Start bounds including `u64::MAX`, and queued/active backward steps at the endpoint.

The review also proposed rebasing the clock when a pending step publishes. That is a different playback policy: the current contract deliberately counts elapsed time since Play, including pending decode time. Existing 5500/9500 ms expectations remain unchanged. The correction does not discard that time or globally remove paused PTS snapping. The native witness additionally requires advancing decoded PTS during playback and first-press restart after a manual endpoint seek; no numeric FPS claim is made.

### UI-04 — Language filtering can misrepresent the committed extraction language

**Impact: moderate.** Search removed options from the selected native `<select>` while retaining the old configuration value. The visible selection could become empty or another language even though extraction would still use the previous language.

**Correction:** the committed select keeps the complete catalog, plus a current configured alias when required. Search has a separate controlled query, result list and active option. Only explicit pointer or Enter selection changes configuration. Escape, Tab/blur, no-match and composing Enter preserve the committed language. Keyboard movement updates `aria-activedescendant`, selection highlighting and listbox-only scrolling; pointer selection returns focus to search. Search does not accidentally change the native job configuration.

**Regression obligations:** deterministic query/choice/cancel/composition tests and alias preservation, plus a native GUI witness that creates an ordinary queue entry and reads its actual persisted language for filtered-query, no-match and explicit-selection phases. Test-created entries are removed afterward. Long-list navigation must keep the active option visible without scrolling the surrounding page/inspector. Persian pointer selection and Japanese composition guards are also checked; the latter is synthetic composition evidence, not physical IME qualification.

### UI-05 — Failed theme initialization leaves canvas/resources behind

**Impact: minor.** The previous initializer appended its canvas before fallible WebGL setup. Missing context, shader/program or buffer failure could return without retiring the canvas; repeated toggles could accumulate abandoned state.

**Correction:** create the canvas off-DOM, own each canvas/shader/program/buffer with deterministic cleanup, and attach only after successful setup. Failed setup drops everything already created. Reusable successful resources remain owned until the final user releases them. A lost context retires its canvas before another engine is admitted. Existing reduced-motion behavior, saved Dark/Light choice and the software-rasterizer backing-buffer cap are retained.

**Regression obligations:** resource lifetime tests plus native WebView failure injection for unavailable context, compile/link/buffer failures, repeated toggles, fallback completion and successful recovery. Restore injected platform methods after the witness. Assert actual resource/canvas cleanup instead of merely checking the theme attribute.

### UI-06 — Fractional frame intervals can reject the last valid millisecond

**Impact: moderate.** The native presentation clock independently rounded the frame timestamp and its duration down to milliseconds. A three-frame 24 fps clip has duration 125 ms, but its last frame was represented as start 83 ms plus duration 41 ms. The strict EOF guard therefore rejected a valid preview at 124 ms. The equivalent 60 fps clip rejected 49 ms even though its duration is 50 ms. Playback deliberately seeks to `duration - 1`, so this can surface as an error at the end of a clip. The pinned Y4M demuxer, raw decoder and frame wrapper confirm the underlying PTS/duration path; this diagnosis did not require changing the decoder or relaxing its EOF contract.

**Correction:** retain the source origin and compute checked source interval endpoints before quantization. Quantize the start and end relative to the same raw origin, then derive duration from their difference. Preserve the missing-duration fallback and reject arithmetic overflow. Fractional positive and negative origins must receive the same normalization; subtracting already rounded absolute timestamps can retain the off-by-one defect.

**Duration scope:** positive decoder durations preserve source interval endpoints at the API's millisecond precision, with its existing 1 ms minimum duration. FFmpeg defines zero duration as unknown. That path retains the documented estimate: initially 40 ms, then the most recent interval clamped to 1–1,000 ms. The positive-duration fixtures do not qualify exact EOF timing for an unknown final interval. No native counterexample with a separately proven final video endpoint was identified in that fallback path. A format-level duration must not be substituted unconditionally for the selected video's exact endpoint.

**Regression obligations:** literal 24/60 fps intervals at zero, fractional positive/negative and whole-second origins, missing-origin initialization, and endpoint overflow. Extend the existing actual native 24/60 fps test to check probe durations 125/50, both legacy and transport previews at 124/49 with the exact last frame's pixels/PTS, rejection at 125/50, and unchanged source bytes. The strict preview EOF check remains unchanged, and this extends the existing four-test native geometry suite.

### UI-07 — Boolean ARIA bindings omit the actual state

**Impact: moderate.** Four bindings passed Rust booleans directly to ARIA attributes: preview busy, two region-selection controls and selected Review cues. Pinned Leptos 0.8.23's boolean attribute renderer writes an empty attribute for true and removes it for false. Those are HTML boolean-attribute semantics, whereas these ARIA states need explicit string values. Assistive technology therefore does not receive the intended state, and a GUI wait using `aria-busy !== 'true'` can mistake a busy preview for an idle one.

**Observed failure:** run 117's Linux x64 GUI witness sampled requested pause time 1507 before its real decoded frame settled to PTS 1500, then reported movement despite playback already being false. This exposed the permissive busy check; it was not evidence that the paused clock kept advancing. The correction addresses the actual DOM state and the witness readiness condition together.

**Correction and regression obligations:** serialize all four ARIA states to literal `"true"`/`"false"`, retain normal HTML `disabled`/`checked` behavior, and require explicit false in GUI idle predicates. Before a stationary observation, require paused playback, no preview owner, a complete real image and agreement between input time and displayed PTS. After the original delay, assert both times and idle state remain identical. Native interactions must exercise selected/unselected region and cue states; the held-response witness observes actual busy true-to-false transitions. Preserve all deadlines and exact postcondition checks.

### CI-01 — Pinned WebDriver click overrides the language handler's focus

Run 118 reached the corrected language witness after successful source-PTS transport, pause/manual-seek and ROI state checks. Persian selection committed correctly and dismissed its popup, but the subsequent focus assertion failed. The pinned WebDriver's generic element-click implementation calls `el.click()` and then unconditionally calls `el.focus()`, without dispatching `mousedown`. That bypasses the control's cancellation of default mouse focus and overwrites the application's explicit return to the search input. The Extract component and its input remain mounted; this receipt does not justify an unrelated production focus timer.

The focus-sensitive witness now exercises a programmatic mouse sequence in the real native WebView: dispatch cancelable primary-button `mousedown`, honor its cancellation before any default focus, then deliver `mouseup` and `click`. It preserves the focus assertion and validates stable input identity, correct committed configuration and dismissal for both choice and clear controls. Clear must restore focus after another control has received it. Keyboard commit and ordinary blur/navigation must not steal focus. The receipt records the sequence and diagnostic focus state and labels it as programmatic interaction rather than physical pointer qualification. No timeout was increased, assertion removed, dependency substituted or production focus workaround added. Exact-source hosted execution remains required.

This corrects the witness, not a demonstrated production Queue-start defect. Do not enable completed rows, clear the queue, choose the first enabled filename, invoke `queue_start` directly, raise the extraction deadline or remove the pixel assertion.
