# Source integrity, review lifecycle, and publication audit

## Scope and evidence

This audit starts at `0c569b0fc8e1a04f602c6e54354d4152a4069eb1` and is tracked by [Issue 16](https://github.com/KiaroSama/Numera-Video-Sub-Finder/issues/16). It covers the core, application, native media adapter, CLI, desktop host, frontend, and build/release orchestration. The fixes are intentionally integrated because source identity, checkpoint ownership, native grants, and frontend state cross crate boundaries.

[Baseline Final verification](https://github.com/KiaroSama/Numera-Video-Sub-Finder/actions/runs/45065883522) passed. That result verifies the baseline only. The audit PR must carry a new manual Final verification on its exact final head; its run, job results, and named test receipts are the source of truth for execution. Formatting and source inspection do not establish a test pass. This document deliberately does not embed its own final commit hash, avoiding a documentation commit that invalidates the evidence it reports.

Compilation and application/test execution remain hosted-only under the repository policy. The four supported native targets remain Windows x64/ARM64 and Linux x64/ARM64. No coverage or mutation floor, signature admission, model assertion, or native deadline is weakened.

## Findings and implemented contracts

### A01 — Output aliases can destroy source media (P1)

The atomic writer honors overwrite consent but cannot infer that a requested output is the input video. Subtitle export, generated per-track output, project save, preview PNG, and crop-evidence export could consequently replace the source. Atomic replacement protects against partial bytes, not choosing the wrong file.

The shared storage admission resolves source/destination aliases before publication. Project-aware writers also use the recorded source fingerprint when a legacy relative or unavailable source cannot provide a stable location. New extraction projects persist canonical source identity before computing the configuration fingerprint. Legacy configuration migration remains conditional on the exact original source/model/configuration identities. Export preflights the entire generated output set, so rejection cannot leave an earlier track written. A distinct hard-link name remains safe where atomic replacement leaves the source name and bytes intact.

Regressions preserve literal source bytes for direct and normalized destinations, symlink aliases, generated-track collisions, project save, valid PNG crop export, and legacy relative source identity. Separate safe output and hard-link replacement remain admitted. See `crates/app/src/storage.rs`, `crates/app/src/export.rs`, `crates/app/tests/export.rs`, and the CLI preview/evidence tests.

### A02 — Resume selects the wrong checkpoint (P1)

The CLI loaded the requested project's configuration but passed only that configuration to extraction. Extraction then independently chose the output-derived `.nvsf.json`, silently ignoring corrections/progress in the selected copy.

The selected canonical path now travels from CLI resume through worker arguments to extraction. The checkpoint owner loads and persists that path, preserves the shared output lock, and acquires a separate selected-checkpoint lock where necessary. Missing/malformed/removed selected projects fail without fallback. Checkpoints, export destinations, and lock paths must not alias: replacing a locked checkpoint inode would otherwise allow a second worker to acquire the replacement while the first is still running.

Tests use two different real project files, missing/malformed/deleted selections, simultaneous output-lock contention, selected/output collisions, and checkpoint/lock collisions. See `crates/cli/src/resume*.rs` and `crates/app/src/extraction_checkpoint*.rs`.

### A03 — Fail-fast disconnects user cancellation (P1)

The pool substituted an internal failure-stop token for the caller's cancellation token. Ctrl-C still changed the original token, so an already-running fail-fast job did not see it. Runners now receive the caller control; internal failure sets that cancellation token as well as the distinct scheduling stop-reason flag.

Deterministic bounded pool tests cover caller cancellation after admission and failure cancelling an already-running peer. They exercise actual scheduling/classification with only native extraction substituted; they are not an OS signal-delivery test. See `crates/cli/src/bulk_tests.rs`.

### A04 — Structural edits retain stale review approval (P2)

Split cloned approval into both changed intervals; merge kept approval from its first cue even if the second cue was unreviewed. Both operations now clear approval on every result. Undo restores the previous states and redo restores unreviewed edited states. Core tests and actual CLI merge/inspect persistence cover the contract.

### A05 — Merge loses original OCR evidence (P1)

Merge combined corrected text but retained only the first cue's raw OCR. Revert after saving then lost the second observation. The fix combines raw observations separately from corrected text and validates the merged cue before changing the vector. Oversized combined raw evidence fails with both original cues retained. The persisted CLI merge/revert regression checks both subtitles survive. The existing single representative crop/confidence schema is unchanged.

### A06 — Bulk SRT ignores encoding flags (P2)

Extraction emitted default SRT and the configurable re-export path ran only for non-SRT formats. Bulk now re-exports its own successful extraction output when BOM/CRLF is requested. It does not grant consent to replace an output that existed before extraction. Tests assert independently specified bytes for all four BOM/CRLF combinations and preserved prior bytes on refused replacement.

### A07 — Resume after a long pause trips idle supervision (P2)

Paused polling skipped the idle check but retained the pre-pause progress timestamp. The first resumed poll could therefore terminate a healthy worker. The pause-aware idle clock subtracts paused duration while preserving active elapsed time. Deterministic `Instant` arithmetic covers long pauses, boundary values, and progress during pause; the separate 24-hour wall deadline remains intact.

### A08 — Preview/re-recognition picks a later frame (P1)

At 25 fps, requesting 39 ms selected the frame at 40 ms instead of the frame displayed since 0 ms. The native JSON request now has a defaulted preroll option. Preview seeks backward and selects the last frame with source PTS at or before the requested time; the following frame proves the preceding interval, while final-frame duration bounds EOF. Ordinary extraction still excludes frames before its requested start.

Pure tests cover variable frame intervals and missing predecessors. A real three-frame Y4M fixture exercises actual native decoding, distinct pixels, exact/between/EOF requests, and unchanged extraction filtering. The sanitizer requires all three geometry tests and their three live loaded-library receipts; the added production selector is included in its provenance inventory. The C ABI entrypoint/layout is unchanged.

### A09 — Required GPU operation initializes optional CPU OCR (P1)

The optional Tesseract verifier could initialize despite required GPU/accelerator policy. It is now suppressed under either requirement, with an explicit warning and existing low-confidence review semantics. The resource fingerprint reflects the effective verifier policy so installing an unused CPU verifier does not alter a required-GPU checkpoint identity. Policy/fixture tests do not establish physical GPU throughput or provider-placement qualification.

### A10 — Corrupt same-version runtime cannot be repaired (P1)

After building and admitting a verified stage, repair rejected an existing corrupt manifest-hash destination rather than replacing it. Activation now retains previous bytes until promotion and selection succeed, restores them on failure, and retains recovery evidence if rollback itself fails. The selection file participates in rollback: an atomic pointer replacement can succeed before a later directory-sync error is returned.

Real-directory tests cover corrupt replacement, healthy reuse, stage and selection publication failures, and an injected failure after the new selection bytes have actually been written. Source review also confirms that activation rejects symlink destinations. The injected filesystem path is not a claim that a real disk failure was induced or that a new signed remote download was exercised.

### A11 — Drag-and-drop command/event ACL is incomplete (P1)

The UI subscribed to a native event whose core listen permissions were absent, and the drop command was missing from the generated command/permission allowlist. Listener failure was swallowed. Both production and instrumented capabilities now grant only listen/unlisten and the required application command; subscription failure is visible. Actual GUI witnesses exercise the event subscription and command route.

### A12 — Drop grants need native-event ownership (P1, latent boundary)

The blocked baseline command accepted frontend-provided paths. Enabling its ACL without changing that contract would let frontend code fabricate filesystem grants. The host now retains the native batch and emits only a one-use token. The command consumes that batch after token validation; fabricated and replayed tokens fail, and a wrong token does not consume the valid pending batch. A new native drop invalidates the older batch. The baseline ACL denial is why this finding is described as latent rather than an already reachable arbitrary-file grant.

Unit tests and the actual frontend/native event witness cover token ownership/replay. The witness emits the application's real event from the instrumented host; it does not simulate an OS-level mouse drag gesture.

### A13 — Dropped-directory traversal is unbounded (P2)

Depth and accepted-video limits did not bound the number of nonvideo entries scanned; eager collection could allocate an entire wide directory before the cap mattered. Traversal now has a shared entry budget, bounded pending roots, and early video-cap termination. Truncation is reported instead of silently looking complete. Regression fixtures exercise broad directories and exhausted budgets.

### A14 — Stale OCR suggestions cross projects/revisions (P1)

The cue editor persisted while `Some(project)` changed to a different `Some(project)`. Its local suggestion contained only cue ID and recognition, allowing an old video's proposal to match a reused ID. Proposals now carry their originating project revision and cue. Project replacement, editing, and selection changes invalidate them; acceptance checks the binding again. Tests use actual edit history, and the GUI witness verifies a later edit invalidates a proposal.

### A15 — Review state can be overwritten during job completion (P1)

An earlier project remained editable during a new extraction. Terminal status could also become visible before awaited queue/current-project requests completed, allowing a new job or edits while the previous watcher still replaced the project and cleared flags. Admission now includes the entire result-loading handoff, not only the worker's active state. New-job/project replacement and review mutation remain unavailable until that handoff finishes. Ordered tests cover successive jobs and attempted edits between terminal status and result installation.

### A16 — Undo dirties an empty workspace (P2)

Ctrl-Z before loading a project could set dirty state without a saveable project, blocking later actions. Shared edit admission requires a project as well as an idle review state. The GUI witness presses the actual undo/redo shortcuts before loading and checks that the workspace remains clean and usable.

### A17 — Stable release bypasses full qualification (P1)

The full gate had `if: !inputs.publish_release`, so publishing skipped the gate it needed. [Release run 45079243130](https://github.com/KiaroSama/Numera-Video-Sub-Finder/actions/runs/45079243130) demonstrates the skip followed by a stable publication. The new publication admission validates successful/completed manual Final verification, the exact source SHA, both repository identities, workflow path, and workspace-version tag. Stable publication and qualification-only runs use the existing full release gate. Only an explicitly requested development prerelease may use development-level native reports.

Tag identity is checked before staging; published input is passed through environment variables rather than direct shell interpolation. An existing stable release rejects development uploads before any asset write, including invalid channel metadata. Tests cover all channel choices, missing full/native evidence, mismatched/failed/foreign verification runs, full positive qualification fixtures, and the actual publish shell body with only `gh` substituted to record writes. No release was created, edited, or deleted by this audit.

## Dependency maintenance

`fuzz` and `ci/loom` are independent Cargo workspaces with their own lockfiles. Both now have bounded weekly Dependabot entries and individually captured advisory audits. The root-workspace audit and license/source policy remain. This closes a maintenance coverage gap; it is not a claim that an undisclosed dependency vulnerability existed.

## Review and completion

Independent integration review checked the cross-boundary corrections and identified additional lock-alias, relative-source, async-handoff, release failure-order, and post-pointer-publication cases. Those cases are included in this change rather than deferred follow-ups. The PR review must inspect their executed regressions alongside the existing native, portable, GUI, security, and source-analysis lanes.

Physical-device GPU evidence, independent real-language annotations, and installation lifecycle qualification must retain their actual measured states. Hosted fixture success must not be promoted into those claims. Stable release remains blocked until the full existing product-qualification contract is genuinely satisfied. The owner/reviewing agent controls merge and closure; the audit author does neither.
