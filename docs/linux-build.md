# Linux build and distribution

Build only in GitHub Actions using native Ubuntu 24.04 x64 and ARM64 runners. Provisioning uses pinned dynamic-release vcpkg triplets, native FFmpeg/Tesseract and the exact ONNX Runtime CPU archive. Build prerequisites include autoconf/autoconf-archive/automake/libtool for pinned gperf/font dependencies, plus NASM, WebKitGTK 4.1 and GTK/platform libraries; Xvfb/Openbox provide an isolated test display. Rust media compilation receives its owned FFmpeg include/library prefix explicitly through `FFMPEG_DIR`. Linux GTK/WebKit pkg-config and linker discovery are not globally prefixed by the separate vcpkg media/font stack: a bounded `--libs --cflags` admission checks the real system GUI dependency closure, preventing a newer owned HarfBuzz from shadowing Ubuntu's exact-match font dependencies. Runtime/package ABI validation remains required; metadata admission alone is not a GUI pass. No WSL, Docker, Rust, Python or Node runtime is required by the installed application itself.

Portable executables search $ORIGIN/runtimes. Installed /usr/bin executables use the package's /usr/lib/Numera Video Sub Finder/runtimes directory. Libraries have $ORIGIN internal search paths; verified models/resources are separate from writable user state. AppImage, deb, rpm and portable tar.gz are generated from target-correct production GUI/CLI bytes with native notices and official icons.

An Ubuntu-hosted build is not proof of every Linux distribution or minimum glibc compatibility. WebKitGTK/system graphics dependencies, clean artifact-only launch, ABI inventory and installation/update/uninstall/data-retention need actual evidence. CPU packages do not imply a CUDA runtime or physical GPU qualification. See platform support and CI reports.

The AppImage bundler can rewrite ELF loader paths, including the packaged visual helper. The bundle stage normalizes only its copied helper to `$ORIGIN` before recording payload hashes; source portable inputs stay unchanged. Installed helper machine type, exact final hash/length and RPATH are checked. Mismatches identify the exact relative member instead of a generic failure. On exact `2d39531` and again `3667346`, both passed the actual AppImage/deb/rpm byte-admission steps after normalization, then failed the separate production-GUI readiness check. This is format evidence, not completed installer lifecycle, production launch or signing qualification.
